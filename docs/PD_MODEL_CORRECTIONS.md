# PD model corrections: evidenced samples and safe scoring

**Status:** synthetic-tested software corrections. No authentic LendingClub event panel has been found, and no real-data PD, AUC, Gini, calibration or scorecard result has been reproduced.

## Evidence path into the existing model

The existing WoE, logistic and scorecard classes remain the modelling components. [`build_model_rows`](../src/creditrisk/data/pd_foundation.py) now bridges the [Phase 2 dated outcome contract](PD_TARGET_FOUNDATION.md) to the existing train/test/OOT inputs. It accepts only explicitly selected, policy-approved features whose per-row availability timestamps are no later than `decision_at`. It uses the confirmed event date in `(origination, origination + 12 calendar months]`, or a fully observed, complete-history non-default. Censored and undated-default rows are counted and excluded; records outside the named cohorts are counted separately. `train`, `test` and `oot` must be chronological and separated by a full 12-month label-observation gap; the as-of date must also follow the OOT end by 12 months. This conservative design avoids using labels from a still-maturing preceding cohort when the next cohort begins.

[`run_sampling.py`](../src/creditrisk/data/run_sampling.py) now accepts **only** `--evidence-jsonl` and `--policy`; it no longer turns the old single-snapshot CSV into model samples. The JSONL rows must use the normalized fields in [PD_TARGET_FOUNDATION.md](PD_TARGET_FOUNDATION.md), including event date/type/source, observation completeness, feature values and timestamps. The reviewed policy JSON must contain exactly `as_of_date`, `cohorts` (named `train`, `test`, `oot`, each with `start` and exclusive `end`), `approved_features`, `selected_features`, `source_description` and `input_sha256`. The last field must be the SHA-256 of the **normalized JSONL**. Dates and feature approval must be reviewed against the upstream source before use. A matching hash proves file consistency, **not** authenticity or completeness of the event ledger.

After validation, the runner writes `data/pd_evidenced/{train,test,oot}.parquet` with selected decision-time features, `loan_id`, `origination_date` and binary `default_12m`. Its ignored `data/pd_evidenced/pd_evidence_manifest.json` records source assertions, cohort windows, sample/exclusion counts and sample hashes. Existing [binning](../src/creditrisk/features/run_binning.py), [PD fitting](../src/creditrisk/models/run_pd_model.py), [scorecard](../src/creditrisk/models/run_scorecard.py), [validation](../src/creditrisk/validation/run_validation.py) and [recalibration](../src/creditrisk/models/run_calibration.py) runners now read that directory and refuse missing or changed samples. Their new generated tables, figures and models go under ignored `outputs/pd_evidenced/`, leaving committed historical tables untouched. Fitted binner, IV table, model pickles and validation summary receive sidecar bindings to the exact sample manifest. The Parquet path requires `pyarrow`, now declared in the dependency manifests. These checks prevent accidental mixing of old target outputs with new samples; they do not replace independent source validation.

The pipeline order remains sampling → train-only WoE/IV → Model A/B fitting → scorecard and validation → optional calibration. Training uses only train rows for bins, IV and coefficients. The test and OOT sets must remain separate from those fit operations. `run_calibration.py` fits its adjustment on test, so its recalibrated test rows are labelled `calibration_fit`; OOT can evaluate that fixed adjustment only if it has not been used for candidate selection. The current runners do not implement a complete model-selection protocol or a production calibration decision.

## Numerical and scoring behavior

[`WoEBinner`](../src/creditrisk/features/binning.py) still uses 0.5-smoothed good/bad shares and train-only IV, and [`PDModel`](../src/creditrisk/models/pd_model.py) still fits a bad-event logistic regression. Categorical nulls now enter `MISSING` before string conversion. Unseen categories route to `OTHER` only when that bin was learned during fit; otherwise WoE transformation raises a clear error. Numeric cut points that would collapse to the same two-decimal displayed boundary are rejected rather than represented ambiguously. `PDModel.fit` refuses missing or nonbinary targets. [`score_dataset`](../src/creditrisk/models/scorecard.py) applies the binner's same bin mapping and refuses missing inputs or absent point bins; it no longer assigns zero points to an unknown bin.

The original score factor, offset, good:bad odds convention and per-bin integer rounding are preserved. The integer score is an approximation to the unrounded logistic score; the total point-rounding difference is bounded by half a point per selected feature. [KS](../src/creditrisk/validation/metrics.py) now evaluates separation after each distinct predicted score, never partway through a tied group. AUC/Gini, Brier and the historical output tables have not been recomputed.

## Limits and historical outputs

The original CSV, dated earliest-default ledger, observation endpoints, feature timing proof and saved model pickles are absent. No source-specific adapter to the normalized JSONL exists. The committed tables under [`outputs/tables/`](../outputs/tables) are **historical, unverified results from the legacy target**. Their values are preserved, not evidence of the corrected path. The historical [`target.py`](../src/creditrisk/data/target.py), notes and archived [model manual](archive/MODEL_DOCUMENTATION.md) remain available to explain the old approach.

Focused synthetic tests cover target admission, cohort gaps, feature timing, manifest/artifact mismatch, null/unseen bins, missing score inputs, score-to-PD parity within rounding tolerance, censored target rejection and tied-score KS. They do not validate a LendingClub model. Before any real fit, obtain an authorised, versioned loan-event panel; authenticate its upstream snapshot, map the earliest qualifying default and observation endpoint, verify every decision-time feature, freeze cohort policy and source hash, then review the exclusion counts. Independent later-cohort discrimination and calibration must follow without selecting the final model on that cohort.
